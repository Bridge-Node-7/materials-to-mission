# Maintenance

Keep the public method, evidence semantics, accessibility behavior, and human decision authority stable unless a change is deliberately versioned and validated.

## Repository shape

- Record release history in `CHANGELOG.md`, Git tags, and GitHub Releases.
- Do not add one release-note file per version to `main`.
- Keep versioned files only when multiple versions must coexist as supported contracts, compatibility fixtures, or immutable reference data.

## User-facing integrity

- Preserve native dialog behavior, accessible naming, and focus restoration.
- Preserve the controlled Atlas conventions and visible evidence gaps.
- Keep M0 maturity and human consequential authority explicit.
- Treat material hosting and accessibility limitations as user-facing facts when they affect interpretation or use.

## Secret incident and history rewrite

A forward cleanup commit is not history sanitization. If a real secret or protected datum is committed, revoke or rotate it first, assess exposure, explicitly authorize any history rewrite, use purpose-built rewrite tooling, then revalidate tags, release provenance, manifests, and downstream clones. Do not rewrite history for cosmetic cleanup.
