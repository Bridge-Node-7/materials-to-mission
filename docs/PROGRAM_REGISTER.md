# Public Program Register

## Purpose

This register preserves durable public-safe decisions and future options without turning
the public repository into a transcript, private customer workspace, legal opinion, or
enterprise operating manual.

Materials-to-Mission is maintained through the personal GitHub account `Bridge-Node-7` as
an individual-scale public demonstration.

## Integrated Public Doctrine

The public method preserves these durable decisions:

- local-first and no telemetry by default;
- synthetic examples remain synthetic;
- public-source snapshots are distinct from private operational cases;
- one canonical public schema authority;
- explicit validation-profile versioning;
- visible unknown, unsupported, contradicted, expired, revoked, and superseded evidence;
- noncompensating critical conditions;
- deterministic validation, rendering, packaging, and release evidence;
- protected-content scanning and fail-closed behavior;
- named human ownership of every consequential disposition;
- no qualification, certification, compliance, adoption, production, or commercial claim;
- minimal website routing only after product release and deployment proof;
- Frontier Decision Engine remains a possible later consumer, not a second schema authority.

## Public Visual Doctrine

The browser is derived, read-only, and non-authoritative.

The interaction grammar is:

**FIELD → FOCUS → PROOF**

The first flagship public journey is:

**Arrival → Materials Atlas → Gallium → Trace to Mission → Show Support → Examine →
Decision Room**

Permanent distinctions include:

- unknown is not contradicted;
- claim support is not pathway assessment;
- governing is not missing;
- triggered is not missing;
- supported claim is not approved pathway;
- evidence-supported action is not human decision.

No composite readiness score or risk dial may average away a critical condition.

## Private Evidence Path

real case record belongs in this public repository absent an explicit sanitized-release
decision.

## Evidence-Gated Future Options

These options remain deferred until evidence demonstrates the need:

1. compare materially different cases before stabilizing cross-case fields;
2. build a thin Frontier Decision Engine adapter after repeated workflow need;
3. add continuing-assurance events after continuing use is demonstrated;
4. add guided intake or import only after repeated onboarding friction;
5. publish a sanitized case study only after explicit technical, confidentiality, IP,
   security, export, and release authorization;
6. version any future legal or acquisition authority profile separately from canonical
   material evidence.

## Private-Only Capabilities

Private systems may contain real customers, suppliers, facilities, laboratories, samples,
lots, contracts, protected thresholds, nonpublic measurements, ownership/control analysis,
qualification plans, pricing, schedules, economics, mission weighting, and customer-
specific decisions.

## Permanent No-Go Decisions

Do not:

- create a competing public Materials-to-Mission schema authority;
- publish protected supplier, customer, laboratory, facility, pricing, capacity,
  vulnerability, restricted, export-controlled, classified, or patent-sensitive material;
- describe the toolkit as a compliance engine, certification authority, automatic
  adjudicator, waiver authority, or official filing system;
- convert missing evidence into a low-risk score;
- let a composite score average away a triggered critical condition;
- let automation approve, qualify, terminate, waive, or close a consequential decision;
- build a hosted backend, broad supplier database, or autonomous recommendation engine
  without separate evidence, authority, and security justification.

## Release Rule

Every public change remains evidence-gated: bounded scope, local validation,
public-boundary review, hosted checks, exact-head readback, reviewed merge, and release
discipline proportionate to risk.
